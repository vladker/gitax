## Problem Statement

В меню нет возможности очистить журналы (`journal.json`, `media_journal.json`, `download_journal.json`). Пользователь может захотеть сбросить состояние обработанных репозиториев/медиа/скачиваний без ручного удаления файлов.

## Approach

Добавить пункт меню `[10] Очистить журналы` с под-меню для выбора конкретного журнала или очистки всех сразу.

## Components

### 1. `clear()` на каждый класс журнала

**`Journal.clear()` в `journal.py`:**
- Сброс `self.data` через `_create_empty()`
- `self.save()`
- Логирование

**`MediaJournal.clear()` в `media_archiver.py`:**
- Аналогично

**`DownloadJournal.clear()` в `channel_downloader.py`:**
- Аналогично

### 2. `_manage_journals()` в `GitHubArchiver`

Sub-menu (паттерн `_manage_ignore_list`):
- Показывает статистику всех трёх журналов
- [1] Очистить journal.json — подтверждение → clear()
- [2] Очистить media_journal.json — подтверждение → clear()
- [3] Очистить download_journal.json — подтверждение → clear()
- [4] Очистить ВСЕ — двойное подтверждение → clear() на всех
- [0] Назад

### 3. Изменения в меню

Добавить `[10] Очистить журналы` между `[9] Выход` и обработкой выбора. Обновить подсказку с `[1-9]` на `[1-10]`.

## Data Flow

```
Пользователь → [10] Очистить журналы
    → _manage_journals()
        → Показ статистики (читаем файлы, считаем записи)
        → Выбор 1-3:
            → Подтверждение [y/N]
            → journal.clear()
            → "✓ Журнал очищен"
        → Выбор 4:
            → "Введите 'ДА' для подтверждения"
            → all three .clear()
            → "✓ Все журналы очищены"
        → Выбор 0: назад
```

## Testing

- `clear()` сбрасывает данные в пустое состояние
- `clear()` вызывает `save()` (файл на диске пустой)
- `clear()` на пустом журнале не падает
- sub-menu отображается и обрабатывает ввод
