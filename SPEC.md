# GitHub Archiver — Техническое задание

## 1. Цель и назначение

Программа для резервного копирования популярных GitHub-репозиториев в мессенджер MAX. При блокировке GitHub пользователь сохраняет доступ к кодам через хранилище мессенджера.

**Основной сценарий:**
1. Пользователь запускает программу
2. Программа скачивает репозиторий в ZIP
3. Отправляет описание + файл в канал MAX
4. Удаляет временный файл
5. Повторяет до достижения лимита

---

## 2. Архитектура решения

### 2.1 Компоненты

| Компонент | Назначение |
|-----------|------------|
| `config.yaml` | Конфигурация (токены, URL, лимиты) |
| `github_archiver.py` | Главный скрипт — меню, циклы, логика |
| `github_api.py` | Работа с GitHub API (поиск, метаданные, скачивание) |
| `browser_max.py` | Автоматизация браузера (Playwright) для отправки в MAX |
| `journal.py` | Ведение журнала (чтение/запись JSON) |
| `logging_config.py` | Настройка логирования (archiver.log) |
| `requirements.txt` | Python-зависимости |
| `temp/` | Временная папка для ZIP-файлов |

### 2.2 Стек технологий

- **Язык:** Python 3.10+
- **GitHub API:** requests (REST API v3)
- **Браузерная автоматизация:** Playwright (CDP к существующему Chrome)
- **Конфигурация:** PyYAML + python-dotenv
- **Хранение данных:** JSON (journal.json)

## 3. Конфигурация

### 3.1 Структура config.yaml

```yaml
github:
  token: "ghp_xxxxxxxxxxxxxxxxxxxx"  # Personal Access Token (или в .env)

max:
  channel_url: "https://web.max.ru/-74679979529682"  # (или в .env)

archiver:
  limit: 100                # Сколько репозиториев обработать
  retries: 3               # Повторы при ошибке загрузки в MAX
  retry_delay: 10          # Пауза между повторами (сек)
  repo_delay: 30           # Пауза между репозиториями (сек)
  split_threshold_mb: 49   # Порог разделения на 7z-тома (МБ)
  use_local_browser: false # false = CDP к Chrome, true = запустить новый
  output_dir: "./temp"     # Временная папка для zip
```

### 3.2 Параметры

| Параметр | Описание | Пример |
|----------|----------|--------|
| `github.token` | GitHub Personal Access Token (env: `GITHUB_TOKEN`) | `ghp_...` |
| `max.channel_url` | URL канала MAX для отправки (env: `MAX_CHANNEL_URL`) | `https://web.max.ru/...` |
| `archiver.limit` | Общее количество репозиториев для обработки | `100` |
| `archiver.retries` | Количество попыток при ошибке | `3` |
| `archiver.retry_delay` | Задержка между попытками (сек) | `10` |
| `archiver.repo_delay` | Пауза между репозиториями (сек) | `30` |
| `archiver.split_threshold_mb` | Порог разделения на 7z-тома (файлы больше — сплитятся) | `49` |
| `archiver.use_local_browser` | false = CDP, true = запустить новый Chrome | `false` |
| `archiver.output_dir` | Папка для временных файлов | `./temp` |

## 4. Журнал (journal.json)

### 4.1 Структура файла

```json
{
  "repositories": [
    {
      "full_name": "microsoft/vscode",
      "display_name": "VSCode",
      "description": "Visual Studio Code - editor for building and debugging",
      "version": "1.14.4",
      "version_type": "branch",
      "stars": 159000,
      "forks": 28500,
      "github_url": "https://github.com/microsoft/vscode",
      "zip_url": "https://github.com/microsoft/vscode/archive/refs/heads/main.zip",
      "downloaded_at": "2025-01-13T10:30:00Z",
      "status": "sent"
    }
  ],
  "last_updated": "2025-01-13T10:30:00Z",
  "total_processed": 50,
  "total_sent": 48,
  "total_failed": 2
}
```

### 4.2 Поля репозитория

| Поле | Тип | Описание |
|------|-----|----------|
| `full_name` | string | Полное имя `owner/repo` |
| `display_name` | string | Короткое имя (алиас) |
| `description` | string | Описание из About репозитория |
| `version` | string | Текущая версия (номер релиза или хеш коммита) |
| `version_type` | string | `release` или `branch` |
| `stars` | integer | Количество звёзд |
| `forks` | integer | Количество форков |
| `github_url` | string | Ссылка на GitHub |
| `zip_url` | string | URL для скачивания ZIP |
| `downloaded_at` | string | ISO timestamp загрузки |
| `status` | string | `sent` / `failed` / `skipped` |

### 4.3 Статусы

| Статус | Значение |
|--------|----------|
| `sent` | Успешно отправлен в MAX |
| `failed` | Ошибка после всех retry |
| `skipped` | Пропущен пользователем |

## 5. GitHub API

### 5.1 Эндпоинты

| Операция | Метод | URL |
|----------|-------|-----|
| Поиск топ-репозиториев | GET | `/search/repositories?q=stars:>1&sort=stars&per_page={limit}&page=1` |
| Метаданные репозитория | GET | `/repos/{owner}/{repo}` |
| Последний релиз | GET | `/repos/{owner}/{repo}/releases/latest` |
| Скачать zip (ветка) | GET | `/repos/{owner}/{repo}/zipball/{ref}` |
| Скачать zip (релиз) | GET | `/repos/{owner}/{repo}/zipball/{tag}` |

### 5.2 Получаемые данные

**При поиске топ-репозиториев:**
- `full_name` — owner/repo
- `description` — About-описание
- `stargazers_count` — звёзды
- `forks_count` — форки
- `default_branch` — ветка по умолчанию

**При детальном запросе:**
- Описание, язык, размер, лицензия
- Последний релиз (тег, версия, дата)
- Дата последнего коммита

### 5.3 Приоритет получения версии

1. Последний релиз (тег вида `v1.2.3`)
2. Если релизов нет — хеш последнего коммита на default_branch
3. Если нет коммитов — "unknown"

### 5.4 Скачивание

- Формат: ZIP-архив
- Источник: default_branch (main или master)
- Имя файла: `{owner}-{repo}-{ref}.zip`
- Папка: `config.output_dir`

## 6. Автоматизация браузера (MAX)

### 6.1 Инструменты

- **Playwright** (`sync_api`) — управление Chrome через CDP (порт 9222)
- Режим: headed (существующий браузер пользователя)
- CDP-подключение сохраняет сессию/cookies — не требует логина

### 6.2 Алгоритм отправки одного файла

```
1. Подключиться к Chrome через CDP (localhost:9222)
2. Перейти на MAX channel_url
3. Дождаться загрузки страницы (networkidle)

4. ОТПРАВИТЬ ТЕКСТОВОЕ СООБЩЕНИЕ:
   - Найти поле ввода ([contenteditable], [role="textbox"])
   - Вставить текст через clipboard (pyperclip)
   - Нажать Enter

5. ЗАГРУЗИТЬ ФАЙЛ:
   - Нажать кнопку загрузки ([aria-label="Upload file"])
   - Дождаться file chooser (Playwright)
   - Выбрать файл через file chooser или input[type=file]

6. ДОЖДАТЬСЯ ЗАГРУЗКИ (основные методы):
   a) MutationObserver — отслеживает DOM на появление файлового сообщения
   b) Проверка индикатора прогресса (%, ширина progress bar)
   c) Проверка ленты на наличие файла с конкретным именем
   d) Проверка DOM на готовность файла в композере

7. ОТПРАВИТЬ СООБЩЕНИЕ С ФАЙЛОМ:
   - Нажать Enter

8. ПОДТВЕРДИТЬ ДОСТАВКУ:
   - Сканировать новые сообщения от baseline-счётчика
   - Проверить, что в сообщении присутствует точное имя файла
   - Проверить наличие кнопки скачивания и индикатора размера
```

### 6.3 Многотомная отправка (7z split)

Если ZIP-файл больше `split_threshold_mb` (по умолчанию 49 МБ):

```
1. Разделить файл на тома через 7-Zip (7z a -v49M -mx=0)
2. Создаются файлы: repo.zip.7z.001, repo.zip.7z.002, ...
3. Текстовое сообщение отправляется ОДИН раз (описание репозитория)
4. Каждый том отправляется отдельным сообщением:
   → Том .001 → дождаться подтверждения → удалить .001
   → Том .002 → дождаться подтверждения → удалить .002
   → ...
5. При подтверждении проверяется ПОЛНОЕ имя файла (включая .7z.003)
6. Это предотвращает ложное совпадение с предыдущими томами
```

### 6.4 Система подтверждения

Каждый этап загрузки проверяет, что в ленте появилось сообщение
именно с текущим файлом, а не с любым `.zip`:

| Метод | Файл | Описание |
|-------|------|----------|
| `_install_upload_observer` | `browser_max.py` | MutationObserver с проверкой имени |
| `_check_upload_in_lenta` | `browser_max.py` | Сканирует ленту, фильтрует по имени |
| `_wait_for_file_message` | `browser_max.py` | Мониторит новые сообщения, матчит имя |
| `_wait_upload_complete` | `browser_max.py` | Основной цикл ожидания с тремя проверками |

Все три точки используют **фильтрацию по полному имени файла** — это
исключает ложные срабатывания на ранее загруженные тома.

### 6.5 Формат текстового сообщения

```

🔖 Версия: {version} ({version_type})
```

## 8. Режимы работы

### 8.1 Ручной режим (по умолчанию)

- После каждого репозитория ожидается действие пользователя
- Enter = загрузить, S = пропустить, Q = выход

### 8.2 Автоматический режим ("A" для всех)

- Пользователь выбирает "A" один раз
- Все оставшиеся репозитории загружаются без подтверждения
- При ошибке: retry N раз → failed → следующий
- Завершается при достижении лимита или конца списка

### 8.3 Пропуск актуальных версий

При синхронизации:
- Если сохранённая версия == актуальная → пропустить без вопроса
- Показать сообщение: "Пропускаю (версия не изменилась)"

## 9. Обработка граничных случаев

| Ситуация | Поведение |
|----------|-----------|
| GitHub недоступен | Сообщение об ошибке, выход в меню |
| Репозиторий не найден | Пропустить, записать в журнал failed |
| Нет релиза и коммитов | Использовать "unknown" как версию |
| ZIP не скачивается | Retry N раз, затем failed |
| MAX не открывается | Retry N раз, затем failed |
| Файл уже отправлен (дубликат) | Пропустить, показать предупреждение |
| Журнал повреждён | Создать новый (старая копия в .backup) |
| Папка temp не существует | Создать автоматически |
| Диск переполнен | Сообщение, выход с сохранением прогресса |

## 10. Безопасность

| Аспект | Решение |
|--------|---------|
| GitHub Token | Хранить только в config.yaml, не в коде |
| Состояние браузера | Не сохранять (.gitignore для *.auth-state.json) |
| Временные файлы | Удалять сразу после успешной отправки |
| Журнал | Не коммитить (добавить в .gitignore) |
